Causal Inference

  • Goal: Estimate the effect of a treatment \(T\) on an outcome \(Y\).
  • Potential outcomes (Neyman, 1923; Rubin, 1974): for each unit \(i\) there are two potential outcomes:
    • \(Y_i(1)\): outcome if treated
    • \(Y_i(0)\): outcome if not treated
  • Individual treatment effect: \(\tau_i = Y_i(1) - Y_i(0)\)
  • Average treatment effect: \(\text{ATE} = \text{E}[Y(1) - Y(0)]\)

The Fundamental Problem of Causal Inference

We never observe both \(Y_i(1)\) and \(Y_i(0)\) for the same unit. One potential outcome is always missing: the counterfactual.

\[ \text{Observed: } Y_i = T_i \cdot Y_i(1) + (1 - T_i) \cdot Y_i(0) \]

A naive comparison of treated and untreated units can be biased because the two groups can differ in confounders.

Bayesian Statistics

We use Bayes’ theorem to update our beliefs about parameters \(\theta\) after we observe data \(y\):

\[ \underbrace{p(\theta \mid y)}_{\text{posterior}} \propto \underbrace{p(y \mid \theta)}_{\text{likelihood}} \cdot \underbrace{p(\theta)}_{\text{prior}} \]

  • Prior \(p(\theta)\): domain knowledge before we see the data.
  • Likelihood \(p(y \mid \theta)\): how probable the data is for given parameters.
  • Posterior \(p(\theta \mid y)\): updated beliefs after we see the data.

From Generative Model to Inference

A probabilistic program describes how the data is generated. Before we observe data, every variable has a prior distribution. When we condition on observed data, the same program defines the likelihood. If we read its arrows as causal, the same program is both the causal model and the Bayesian model.

Probabilistic Programming Languages (PPLs)

PPLs let us write generative models as code and run posterior inference automatically. Examples: PyMC, NumPyro, Stan.

Causal Inference and PPLs

In industry, we estimate causal effects from limited data and under assumptions we cannot fully test. PPLs help in the following ways:

  • The model is the DAG: we write the data-generating process as code, so every causal assumption is explicit.
  • Priors: domain knowledge and past experiments enter the estimate.
  • Uncertainty: we get a posterior distribution for every causal quantity.
  • The do operator: we apply interventions to the model and compute counterfactual predictions.
  • Flexible structure: non-linear likelihoods, hierarchical models, latent variables, and measurement models.

PPLs do not solve identification. They help with estimation once we state the causal assumptions.

Bayesian A/B Testing

In an A/B test, we randomly assign users to a control group and a treatment group. Random assignment makes the treatment independent of all confounders, observed and unobserved. The hard part moves from identification to estimation under uncertainty. We observe \(y_\text{c}\) and \(y_\text{t}\) conversions out of \(n\) users per group, and we add a Binomial likelihood for them later.

with pm.Model() as non_informative_model:
    conversion_rate_control = pm.Uniform(
        "conversion_rate_control", lower=0, upper=1
    )
    conversion_rate_treatment = pm.Uniform(
        "conversion_rate_treatment", lower=0, upper=1
    )
    relative_lift = pm.Deterministic(
        "relative_lift",
        conversion_rate_treatment / conversion_rate_control - 1,
    )

\[\begin{align*} \text{cr}_\text{c} & \sim \text{Beta}(1, 1) \\ \text{cr}_\text{t} & \sim \text{Beta}(1, 1) \\ \text{lift} & = \text{cr}_\text{t} / \text{cr}_\text{c} - 1 \end{align*}\]

Correlated Priors

Most lifts are small, so we set the prior on the relative lift itself.

with pm.Model() as correlated_model:
    conversion_rate_control = pm.Beta(
        "conversion_rate_control", alpha=15, beta=600
    )
    relative_lift = pm.Normal(
        "relative_lift", mu=0, sigma=0.1
    )
    conversion_rate_treatment = pm.Deterministic(
        "conversion_rate_treatment",
        conversion_rate_control * (1 + relative_lift),
    )

\[\begin{align*} \text{cr}_\text{c} & \sim \text{Beta}(15, 600) \\ \text{lift} & \sim \text{Normal}(0, 0.1) \\ \text{cr}_\text{t} & = \text{cr}_\text{c} (1 + \text{lift}) \end{align*}\]

Observed Confounders

Without randomization, we must adjust for confounders. We use the LaLonde data from a job training program (National Supported Work Demonstration, 1970s) and ask whether job training increases earnings.

  • Treatment: participation in the job training program (treat).
  • Outcome: earnings in 1978 (re78, in thousands of USD).
  • Covariates: education, age, earnings in 1975 (re75), race and ethnicity, marital status, degree.
  • Naive comparison: the treated group earned \(635\) USD less than the comparison group. The \(185\) treated units come from the experiment, but the \(429\) comparison units come from an observational survey, so treatment was not randomly assigned.

We assume that the covariates block every backdoor path (the backdoor criterion).

Regression and the do Operator

We have two ways to estimate the ATE:

  1. We fit a linear regression and read the estimate of \(\beta_{\text{treat}}\) as the ATE:

    \[ \text{earnings} = \beta_0 + \beta_{\text{treat}} \cdot \text{treat} + \beta_{\text{covariates}} \cdot \text{covariates} + \varepsilon \]

  2. We use the do operator:

    \[ \text{ATE} = \text{E}[\text{earnings} \mid \text{do}(\text{treat} = 1)] - \text{E}[\text{earnings} \mid \text{do}(\text{treat} = 0)] \]

Pearl’s do Operator

  • Conditioning: \(\text{P}(Y \mid T = t)\) describes the units that happened to receive \(T = t\). They can differ from the others in their confounders.
  • Intervening: \(\text{P}(Y \mid \text{do}(T = t))\) describes \(Y\) when we set \(T = t\) for every unit. In the graph, we cut all arrows into \(T\), as in a randomized experiment.
  • Adjustment: if \(X\) satisfies the backdoor criterion (it blocks every backdoor path from \(T\) to \(Y\) and contains no descendant of \(T\)), then \(\text{P}(Y \mid \text{do}(T = t)) = \sum_{x} \text{P}(Y \mid T = t, X = x) \, \text{P}(X = x)\).

The PyMC Model

We write both parts of the DAG as code:

  • covariates \(\to\) treat
  • treat + covariates \(\to\) earnings
with pm.Model(coords=coords) as earnings_model:
    covariates = pm.Data("covariates_data", covariates_obs, dims=("obs_idx", "covariate"))
    # covariates -> treat
    intercept_treat = pm.Normal("intercept_treat", mu=0, sigma=10)
    beta_covariate_treat = pm.Normal("beta_covariate_treat", mu=0, sigma=1, dims="covariate")
    treat = pm.Bernoulli(
        "treat", logit_p=intercept_treat + covariates @ beta_covariate_treat, dims="obs_idx"
    )
    # treat and covariates -> earnings
    intercept_earnings = pm.Normal("intercept_earnings", mu=0, sigma=10)
    beta_treat_earnings = pm.Normal("beta_treat_earnings", mu=0, sigma=1)
    beta_covariate_earnings = pm.Normal("beta_covariate_earnings", mu=0, sigma=1, dims="covariate")
    sigma_earnings = pm.HalfNormal("sigma_earnings", sigma=10)
    mu_earnings = pm.Deterministic(
        "mu_earnings",
        intercept_earnings + beta_treat_earnings * treat + covariates @ beta_covariate_earnings,
        dims="obs_idx",
    )
    pm.Normal("earnings", mu=mu_earnings, sigma=sigma_earnings, dims="obs_idx")

Hierarchical Models

An unobserved group effect \(G\) drives \(X\) and \(Y\). The true effect of \(X\) on \(Y\) is zero.

  • Regularization: hierarchies are an effective regularization. The group intercepts come from a common distribution, so partial pooling shrinks noisy group estimates toward the population mean.
  • Fixed and random effects: we can study both through this lens. A hierarchy alone does not make the model better. Here the random intercepts model is still biased.

Marketing Measurement Problem

The Business Question

How should we split next quarter’s marketing budget across channels to maximize sales? To answer it, we need the efficiency of each channel: the extra sales that one more unit of spend brings.

Attribution assigns each conversion to the ads in the user’s path. Last-touch attribution gives all the credit to the last ad. Multi-touch attribution splits it across the tracked ads, with a rule or a data-driven model. Consider a user who sees a Social ad, opens an Email, clicks a Search ad, and buys:

Credit Social Email Search
Last touch \(0\%\) \(0\%\) \(100\%\)
Multi-touch (equal shares) \(33\%\) \(33\%\) \(33\%\)

Attribution Does Not Measure Incrementality

  • Privacy: consent rules (GDPR) and platform changes (Apple’s App Tracking Transparency) remove touchpoints from the paths. Offline channels such as TV were never in them.
  • Incrementality: attribution gives credit for every sale, even when the user would have bought without any ad. We want the extra sales that a channel causes: a do contrast.

Gordon et al. (2019), Marketing Science: observational methods often fail to recover the lift of field experiments.

Marketing Mix Models

In marketing, budgets are rarely randomized, so we estimate channel effects from observational time series. These are aggregate data, for example weekly spend and sales. We need no user-level tracking, and offline channels such as TV are in the data.

A marketing mix model (MMM) is a regression of sales \(y_t\) on transformed media spend \(x_{m,t}\) and control variables \(z_{k,t}\) (trend, seasonality, holidays):

\[ y_t = \beta_0(t) + \sum_{m} \beta_m(t) f_m(x_{m,t}) + \sum_{k} \gamma_k z_{k,t} + \varepsilon_t \]

where \(f_m\) is the media transformation of channel \(m\) (next slide). The intercept \(\beta_0(t)\) and the channel coefficients \(\beta_m(t)\) can vary over time, for example with Gaussian processes.

The data are short (typically \(2\) to \(3\) years of weekly data), the media channels are correlated, and some confounders are unobserved. Bayesian MMMs add domain knowledge through priors, calibration with experiments, and posterior uncertainty for budget decisions.

Jin, Yuxue, et al. “Bayesian methods for media mix modeling with carryover and shape effects.” (2017).

Adstock and Saturation

The adstock transformation models carryover: the effect of an ad persists and decays over time.

\[ \text{adstock}(x_{m, t}; \alpha, L) = \frac{\sum_{j=0}^{L-1} \alpha^{j} x_{m, t-j}}{\sum_{j=0}^{L-1} \alpha^{j}} \]

for \(\alpha \in [0, 1]\) and \(L\) the maximum lag.

The saturation transformation models diminishing returns: each extra unit of spend has a smaller effect.

\[ \text{saturation}(x; \eta) = \frac{1 - \exp(-\eta x)}{1 + \exp(-\eta x)} \]

for \(\eta > 0\).

Adstock: Jin et al. (2017). Saturation: PyMC-Marketing LogisticSaturation.

Return on Ad Spend

An MMM splits sales into a baseline, seasonality, and channel contributions (right).

The return on ad spend (ROAS) of channel \(m\) compares the expected sales with and without the channel, per unit of spend. It is an ATE per unit of spend, for a continuous treatment that was not randomized.

\[ \text{ROAS}_m = \frac{\sum_t \left(\text{E}[y_t \mid \text{do}(x_m = x_m^{\text{obs}})] - \text{E}[y_t \mid \text{do}(x_m = 0)]\right)}{\sum_t x_{m,t}} \]

Calibration with Experiments

As in the A/B test, we put the prior on the quantity we know about: the ROAS.

We write each media coefficient as a function of the channel’s ROAS (simplified, with a constant \(\beta_m\)):

\[ \beta_m = \frac{\text{ROAS}_m \sum_{t} x_{m,t}}{\sum_{t} \left(f(x_{m,t}) - f(\tilde{x}_{m,t})\right)} \]

where \(f\) is the media transformation (adstock and saturation) and \(\tilde{x}_{m}\) is the spend with channel \(m\) turned off.

We can now put a prior on the ROAS of each channel, for example from a past experiment. Here we center the priors at \(95\) and \(170\), close to the truth (scaled data below).

The frugal parameterization of Evans and Didelez (2024) follows a related idea: it makes the causal effect a parameter of the model, so we can put a prior on it directly.

Funnel Models in Marketing

An omitted confounder biased the previous models. Funnels add a different risk: a mediator that we add as a regressor.

We use the PyMC-Marketing MMM case study (\(209\) weeks of synthetic sales data).

  • Upper funnel channels build awareness: TV, Radio, Newspaper.
  • Lower funnel channels capture existing demand, like paid search (search engine marketing, SEM): sem_spend.
  • Paid search is \(26.9\%\) of the modeled media spend. Its spend and impressions (how often the ads show) both correlate with sales (\(0.59\)).

Two stories fit the data: paid search drives sales, or it harvests demand that the upper funnel created. Correlation cannot separate them.

PyMC-Marketing: MMM Case Study II

The Funnel DAG

  • TV, Radio, and Newspaper act on sales directly and through latent demand \(D\).
  • The paid search budget \(B\) adds to \(D\). The sum is the mediator \(M^*\) (the demand that paid search reaches). Here \(B\) is exogenous.
  • Search impressions measure \(M^*\) and do not cause sales. Dashed nodes are latent.
  • In practice, paid search spend also follows demand, so adding it as a channel conditions on the mediator (Chan and Perry, 2017: “Downstream ads should not be included with exogenously-determined ads in a single regression equation.”).

PyMC-Marketing: MMM Case Study II

Funnel Model Intuition

Let’s follow the demand for the product through the funnel in one week.

  • Interest: some people look for the product anyway. TV, Radio, and Newspaper bring more of them, with a lag.
  • Search: paid search ads reach these people. More search spend buys more queries and higher positions, so it reaches extra people.
  • Measurement: we never see this demand. Search impressions grow with it, but they do not cause sales.
  • Sales: the demand that paid search reaches turns into sales. All other channels also act on sales directly.

Search sales are not all search’s doing. The model splits the demand behind them into interest that exists anyway, the upper funnel, and the paid search spend itself.

PyMC-Marketing: MMM Case Study II

Funnel Model Components

We now give each part a symbol. The index \(t\) is the week.

  • Demand pool \(D_t\): a baseline plus what the spend \(U_{t,c}\) of each upper funnel channel \(c\) adds.
  • Search demand \(M^*_t\): the pool \(D_t\) plus the demand that the paid search spend \(B_t\) adds. A parameter \(\lambda \ge 0\) sets the size of this addition. If \(\lambda = 0\), paid search creates no new demand, and its ads only reach people who would search anyway. We estimate \(\lambda\) to split search demand into what was already there and what the spend added.
  • Measurement \(I_t\): the search impressions measure \(M^*_t\). They do not enter the sales equation.
  • Sales \(\mu_t\): the mean of sales is \(\text{MMM}_t\) (the direct terms of the other channels and the controls) plus the sales that \(M^*_t\) turns into. Paid search has no direct term.

PyMC-Marketing: MMM Case Study II

Funnel Model Structure

We write the four components as equations, plus the sales likelihood:

\[ \begin{align*} D_t & = \text{baseline} + \sum_{c \in \text{upper}} \text{sat}^{uf}\left(\text{adstock}^{uf}({\color{#d55e00} U_{t,c}})\right) \\ M^{*}_t & = D_t + \lambda \, \frac{{\color{#d55e00} B_t}}{s_{B}} \\ {\color{#d55e00} I_t} & \sim \text{TruncatedNormal}\left(s_{I} \, M^{*}_t, \sigma_{I}, \text{lower}=0\right) \\ \mu_t & = \text{MMM}_t + \text{sat}^{lf}\left(\text{adstock}^{lf}(M^{*}_t)\right) \\ {\color{#d55e00} y_t} & \sim \text{TruncatedNormal}\left(\mu_t, \sigma, \text{lower}=0\right) \end{align*} \]

The orange quantities are observed (spend, impressions, and sales), and \(D_t\) and \(M^*_t\) are latent. The scales \(s_B\) and \(s_I\) are the maxima of \(B_t\) and \(I_t\). The noise scales are \(\sigma_I\) and \(\sigma\), and \(uf\) and \(lf\) mark the upper and lower funnel.

This is a structural equation model with a latent variable. The impressions equation is the measurement model, and we fix its loading at one to set the scale of \(M^*_t\).

Funnel Model in PyMC-Marketing

The funnel is a custom MuEffect. Its create_effect method builds \(D_t\), \(M^*_t\), and the impressions likelihood, and returns the term that the MMM adds to \(\mu_t\).

class FunnelEffect(DataVarMuEffect):
    def create_effect(self, mmm):  # adds a term to the sales mean mu_t
        # upper funnel spend (TV, Radio, Newspaper), read from the MMM's own channel data
        channel_index = [mmm.channel_columns.index(c) for c in self.upper_channels]
        upper = mmm.channel_data_scaled.isel(channel=channel_index)
        upper = upper.rename({"channel": "channel_upper"})
        # demand pool D_t
        baseline = pmd.HalfNormal("funnel_baseline", sigma=1.0)
        upper_on_demand = self.upper_transform(upper, dim="date").sum(dim="channel_upper")
        demand = pmd.Deterministic("funnel_demand", baseline + upper_on_demand)
        # search demand M*_t
        lam = pmd.HalfNormal("funnel_lambda", sigma=0.5)
        mediator = pmd.Deterministic(
            "funnel_mediator", demand + lam * mmm.model["sem_spend"] / self.sem_scale
        )
        # measurement I_t: the impressions likelihood
        pmd.TruncatedNormal(
            "funnel_sem_impressions_likelihood",
            mu=self.impressions_scale * mediator,
            sigma=pmd.HalfNormal("funnel_sigma_s", sigma=0.2 * self.impressions_scale),
            lower=0.0,
            observed=mmm.model["sem_impressions"],
        )
        # sat_lf(adstock_lf(M*_t)): the term that the MMM adds to mu_t
        return pmd.Deterministic(
            "funnel_effect_contribution", self.demand_transform(mediator, dim="date")
        )

Channel Synergies

The givers TV, Radio, Newspaper, and sem_spend feed the search demand. We set one giver to zero and read what the SEM path into sales loses.

  • No media (intercept): the baseline of \(D_t\), the search demand that exists with all spend at zero (people who look for the product anyway).
  • Reading the \(41\%\): about \(41\%\) of the sales on the search path come from people who search anyway. No channel gets credit for them, so search sales overstate what paid search causes.
  • Pass-through: paid search’s own spend adds \(48\%\). TV, Radio, and Newspaper add about \(10\%\) together, each with an HDI that reaches zero. Only an upper funnel experiment can test this path.

Budget Optimization

Let \(b_m\) be the weekly spend of channel \(m\) that we hold over the planning window, \(B\) the total weekly budget, \([l_m, u_m]\) the guardrails of channel \(m\), and \(R(b; \theta)\) the sales response over the window for the plan \(b\) and the model parameters \(\theta\). We solve

\[ \max_{b} \; \text{E}\left[R(b; \theta) \mid y\right] \quad \text{subject to} \quad \sum_{m} b_m = B, \quad l_m \le b_m \le u_m \]

  • Each plan is an intervention \(\text{do}(x = b)\). The plan relies on the causal estimates of the response curves, so calibration matters here.
  • Because of saturation, the optimizer moves money from channels with a low marginal return to channels with a high marginal return, until the marginal returns match or a guardrail binds.
  • The guardrails keep the plan close to the spend we observed. The posterior gives a distribution of the response for each plan, so we can also optimize a risk-aware utility instead of the mean.

All three plans share the posterior, the \(13\)-week window, the total weekly budget, and the \(\pm 50\%\) guardrails. They differ in the objective and in whether sem_spend can move:

  • Direct-only: maximizes the direct media contribution. It cannot see the path through \(M^*\), so sem_spend stays fixed.
  • Funnel, SEM pinned: maximizes the total response, direct plus mediated, with sem_spend fixed.
  • Funnel-aware: maximizes the total response, and sem_spend can move within its own \(\pm 50\%\) band.

Comparing pinned with direct-only isolates the objective. Comparing funnel-aware with pinned isolates the paid search budget.

Exploration and Exploitation

We do not fit an MMM once. We re-fit it, usually every quarter, and the budget split decides what the next fit can learn.

  • Exploitation: spend where the model already sees the best return.
  • Exploration: spend at other levels so that the next fit can trace the saturation curves.

PyMC Labs: Exploration vs Exploitation in Marketing Budget Allocation

Exploration Policies

In a simulated market with known true curves, we re-fit the MMM every week for a year. The model starts out wrong about a channel that the optimizer does not fund.

  • Baseline: greedy only exploits.
  • Unaimed: eps-greedy moves a slice at random.
  • Aimed at revenue: thompson and ucb are bandit rules (Thompson sampling, upper confidence bound). aggressive re-plans every week.
  • Aimed at learning: directed moves the slice to where the posterior curves disagree most (Bayesian experimental design). annealed explores less over time.
  • Measurement ceiling: spread keeps every channel’s spend moving.

The bars show the extra revenue per year over greedy: the median of \(20\) runs, on \(\$50\text{M}\) of annual revenue.

Simulation Learnings

We compare the policies on what they earn and on what the model learns:

  1. Pure exploitation stops learning. Under greedy, the uncertainty about the largest channel stops shrinking after about two months. When the model underrates a channel, greedy never funds it in any of the \(20\) runs, so it never learns that the model is wrong.
  2. Aim matters more than amount. directed and eps-greedy move a slice equally often, from the same menu of moves. directed aims at what the model is least sure about and finds the underrated channel within weeks. eps-greedy moves at random and finds it in only \(10\) of \(20\) runs.
  3. Bandit rules aim at revenue, not at learning. In a stable market, thompson and ucb end the year with about as much uncertainty as greedy, but they are the cheapest explorers. When the model underrates a channel, ucb finds it as fast as directed.
  4. Exploration is cheap insurance. On \(\$50\text{M}\) of revenue, directed costs about \(\$178\text{K}\) a year more than greedy in a stable market. When the model underrates an unfunded channel, the four fast policies (directed, annealed, aggressive, and ucb) earn about \(\$15\text{M}\) a year more.

If the saturation intervals of your MMM stop narrowing from quarter to quarter, the loop has stopped learning.

Amortized Bayesian Inference

Markov chain Monte Carlo (MCMC) starts from scratch for every new dataset. Amortized Bayesian inference trains a neural network once on simulations from the model.

  • Simulator only: we need draws from the model, not a tractable likelihood.
  • Many refits: after the training cost, each new posterior takes milliseconds.
  • Trust: on data outside the simulations, the network can fail silently.

PyMC Labs: Amortized Bayesian Inference, figure from Stefan Radev’s PyMC Labs webinar

Marketing Foundational Models

Marketing Foundational Models (MFM) apply this idea to MMMs. A model trained on simulated marketing worlds returns the sales contributions of a new dataset in one pass.

  • Causal graphs: each draw samples a plausible causal graph and the sales split under it.
  • Latent truth: contributions are latent, so all tests so far use simulated worlds.
  • Early prototype: it is not yet ready to drive budget decisions on its own.

Takeaways

  • The model states the assumptions. We write the DAG as code.
  • Priors and experiments carry outside information. Lift priors rule out implausible lifts in A/B tests. ROAS priors and lift tests reduce confounding bias in MMMs.
  • The same do query works across models. It applies to regressions, GLMs, MMMs, and funnel models.
  • Hierarchies regularize. They do not replace thinking about the DAG.
  • The causal structure changes decisions. The funnel model tells us how much to spend on paid search.
  • An MMM is a decision loop, not just a model. We fit, calibrate, optimize the budget, spend, and re-fit. Each budget trades earning now against learning for the next fit, and a small, aimed exploration budget keeps the loop learning.
  • Amortized inference trains once. Amortized Bayesian inference and MFM learn from simulations, then handle new data in seconds.
